# Как устроен сайт-портфолио

Этот файл объясняет архитектуру проекта простым языком: где лежат данные, как подключаются направления, как работает витрина и что менять при развитии сайта.

## Общая идея

Сайт построен не как одна большая страница, где все смешано вместе, а как модульная витрина.

Есть три уровня:

1. Данные работ: `data/data.json`.
2. Модули направлений: `src/modules/*`.
3. Общий интерфейс сайта: `src/App.jsx` и `src/App.css`.

Такой подход нужен, чтобы программирование, видеомонтаж и будущие направления могли развиваться отдельно.

## Поток данных

Основной путь данных выглядит так:

```txt
data/data.json
  -> src/modules/registry.js
  -> normalizeProjects()
  -> src/App.jsx
  -> витрина работ
```

`data/data.json` хранит обычный список работ. У каждой работы есть поле `type`.

Например:

```json
{
  "type": "code",
  "title": "Mini Chess Game"
}
```

Или:

```json
{
  "type": "video",
  "title": "SpiderHeck - Путь к 70-й волне"
}
```

По этому полю сайт понимает, какой модуль должен обработать работу.

## Реестр модулей

Файл `src/modules/registry.js` подключает все активные направления:

```js
export const portfolioModules = [programmingModule, videoEditingModule]
```

Если в будущем появится новое направление, например дизайн, оно добавляется сюда:

```js
export const portfolioModules = [
  programmingModule,
  videoEditingModule,
  designModule,
]
```

Если модуль убрать из массива, сайт продолжит работать, просто перестанет показывать работы этого типа.

## Как устроен модуль

Каждый модуль описывает одно направление. Например, `src/modules/programming/index.js`.

У модуля есть:

- `id` - техническое имя направления;
- `title` - название на русском и английском;
- `shortTitle` - короткая подпись для фильтра;
- `description` - описание направления;
- `accepts(project)` - проверка, подходит ли работа модулю;
- `normalize(project)` - приведение данных к общему формату.

Главная идея: разные типы работ могут иметь разные поля, но после `normalize()` интерфейс получает единый формат.

Пример: у код-проекта есть `githubUrl`, а у видео есть `videoUrl`. Модули превращают их в общий массив `links`.

## Данные проектов

Основной контент редактируется в `data/data.json`.

Для код-проекта важны поля:

- `type: "code"`;
- `title`;
- `description`;
- `tags`;
- `date`;
- `code.githubUrl`;
- `code.stack`.

Для видео:

- `type: "video"`;
- `title`;
- `description`;
- `tags`;
- `date`;
- `video.videoUrl`;
- `video.duration`;
- `video.role`.

Флаг `featured` сейчас может использоваться для выделения работы в будущих версиях. В текущей витрине показываются все работы выбранного направления плюс демонстрационные пустые карточки.

## Витрина работ

Витрина реализована в `src/App.jsx` компонентами:

- `Showcase`;
- `ShowcaseCard`.

Она работает как карусель.

Состояние хранится здесь:

```js
const [activeModule, setActiveModule] = useState('all')
const [activeProject, setActiveProject] = useState(0)
```

`activeModule` отвечает за фильтр:

- `all` - все работы;
- `code` - программирование;
- `video` - видеомонтаж.

`activeProject` отвечает за центральную карточку.

## Стадии карточек

Карточки расставляются по схеме:

```txt
2 1 2
```

Где:

- `1` - центральная карточка, видна полностью;
- `2` - боковая карточка, меньше и находится позади;
- дальние карточки плавно становятся прозрачными.

В `App.jsx` функция `getCircularOffset()` считает, насколько карточка далеко от активной:

```js
offset = 0   // центр
offset = -1  // слева
offset = 1   // справа
```

В CSS эти значения используются как переменные:

```css
--offset
--abs-offset
```

Через них задаются:

- `translateX`;
- `scale`;
- `opacity`;
- `z-index`.

Именно поэтому карточки двигаются плавно и могут переключаться в обе стороны.

## Пустые карточки

Пустые демонстрационные карточки создаются в `buildShowcaseItems()`.

Они нужны, чтобы витрина уже сейчас выглядела наполненной, даже если реальных работ пока мало.

Их тексты лежат в `src/shared/i18n.js` в секции `placeholders`.

## Темы

Тема хранится в состоянии:

```js
const [theme, setTheme] = useState('dark')
```

На главный контейнер ставится атрибут:

```jsx
<main className="site-shell" data-theme={theme}>
```

В CSS есть базовые переменные для темной темы и переопределение для светлой:

```css
.site-shell {
  --bg: #090d14;
}

.site-shell[data-theme='light'] {
  --bg: #f6f8fc;
}
```

Почти весь дизайн строится на CSS-переменных, поэтому тему можно менять без переписывания компонентов.

## Языки

Тексты лежат в `src/shared/i18n.js`.

Состояние языка:

```js
const [language, setLanguage] = useState('ru')
```

Выбор текста:

```js
const t = copy[language]
```

Если нужно поменять текст на сайте, чаще всего надо идти именно в `i18n.js`, а не искать строку внутри JSX.

## Контакты

Контакты сейчас заданы прямо в `src/App.jsx`:

```js
const contacts = {
  github: 'https://github.com/LakusDVV',
  telegram: 'https://t.me/Vladis_DVV',
}
```

Если появится рабочая почта, ее лучше добавить туда же и заменить текст-заглушку в `src/shared/i18n.js`.

## Как добавить новую работу

Добавить объект в `data/data.json`.

Для нового код-проекта:

```json
{
  "id": "new-project",
  "type": "code",
  "title": "New Project",
  "description": "Краткое описание проекта.",
  "thumbnail": "",
  "tags": ["React", "JavaScript"],
  "featured": true,
  "date": "2026-06-15",
  "code": {
    "githubUrl": "https://github.com/LakusDVV/example",
    "liveUrl": "",
    "stack": ["React", "JavaScript"]
  }
}
```

Для видео:

```json
{
  "id": "new-video",
  "type": "video",
  "title": "New Video",
  "description": "Краткое описание ролика.",
  "thumbnail": "",
  "tags": ["DaVinci Resolve"],
  "featured": true,
  "date": "2026-06-15",
  "video": {
    "videoUrl": "https://www.youtube.com/@Lakus_DVV",
    "duration": "0:00",
    "role": "Монтаж"
  }
}
```

## Как добавить новое направление

1. Создать папку `src/modules/newDirection`.
2. Внутри создать `index.js`.
3. Описать объект модуля по примеру `programmingModule`.
4. Добавить модуль в `src/modules/registry.js`.
5. Добавить проекты с новым `type` в `data/data.json`.

После этого направление появится в фильтрах витрины.

## Что можно улучшить дальше

- Добавить отдельные страницы проектов.
- Подключить реальные изображения-превью.
- Сделать автоподтягивание данных из GitHub API.
- Добавить YouTube-превью через oEmbed или YouTube Data API.
- Сохранить выбранную тему и язык в `localStorage`.
- Добавить рабочий email.
